# Controls: where each requirement is met, and what proves it

One row per requirement a reviewer asks about. Each row names the code that does it and the test
or check that fails if it stops being true. Nothing here is a claim without one of those;
where the repository cannot satisfy a requirement the row says so, and the action is in
`docs/needs-a-person.md`.

How to run the evidence:

```sh
cargo test --workspace --locked          # every test named below (no services needed)
docker compose up --build -d --wait
python3 scripts/e2e.py                   # checks quoted in curly quotes below come from these scripts
sh scripts/verify-storage.sh
sh scripts/verify-operations.sh
python3 scripts/load-test.py
python3 scripts/verify-lifecycle.py      # last: it rotates the stack's encryption key
```

`every_test_the_controls_page_names_exists` and
`the_readme_and_architecture_documents_cover_what_they_must` (`src/api/__test__/controls.rs`)
check that every test, file and quoted check on this page exists.

Status: **Met** = was already true, now demonstrated. **Built** = implemented or completed in
this pass. **N/A** = does not apply to this product, with the reason. **Person** = needs a person
or an organizational decision. **Partly** = true as far as stated, with the gap named.

## Dependencies with known vulnerabilities

`cargo audit`, `npm audit` and `pnpm audit` run in CI (`.github/workflows/checks.yml`).

One advisory is excepted: RUSTSEC-2026-0459 against `libsqlite3-sys 0.37.0`. That crate is in
`Cargo.lock` because `sqlx` 0.9.0 (the latest release) locks its optional SQLite backend whether
or not it is enabled. LoanDesk enables only the PostgreSQL backend: `cargo tree --workspace --target all -e all -i libsqlite3-sys`
prints nothing, and CI fails if that ever changes. It cannot be upgraded from this repository
(`sqlx-sqlite 0.9.0` requires a version below the fixed one). The exception, its reason and when
to remove it are in `.cargo/audit.toml`; it was accepted on 2026-11-16. `cargo audit` reports every
other advisory and fails on it.

## Not done

- **Field encryption of staff email and name.** They are classified as personal data and protected
  by tenant isolation, role restriction and storage encryption, but stored readable: sign-in looks
  users up by email, the user list is ordered by name, and application lists join and search on the
  relationship manager's name. Encrypting them needs a keyed lookup token for the email and gives
  up ordering and substring search on names.
- **Deleting one application on request**, before its retention period ends (`docs/data-classification.md`).
- **An audit-trail screen.** Admins read it through `GET /api/audit-log`; the web app has no page for it.
- **Password reset by email**, and resetting another user's password. A user who forgets their password
  cannot recover the account; an admin has to create a new one.
- **The optional observability profile's telemetry store** still uses the MinIO image's default
  credentials over plain HTTP inside the Compose network (generated ForkLaunch monitoring
  configuration). It holds traces, metrics and logs only, and exists only on a laptop.
